# Case Study 1 of 6: Global E-Commerce Platform

**Scenario:** Solstice Retail Group (fictional, composite)  a mid-market DTC apparel/home-goods retailer, ~$310M revenue, expanding from US/Canada into the UK, Germany, France, Australia, and Singapore. Strong seasonal-elasticity, global-latency, and cost-optimization angle. One of six case studies in the [Cloud Architecture](../README.md) portfolio.

## Scope Note

This case study compares **Azure, AWS, and GCP**  no private-cloud track. Solstice is already cloud-native (a single-region AWS deployment since 2019), and a physical-facility alternative doesn't fit a workload whose entire premise is elastic, bursty demand; three hyperscalers is the right comparison set, not four. Full implementation depth per platform and a full migration roadmap, matching Case Study 3's rigor.

Decision matrix (Azure / AWS / GCP) | Done — [`docs/decision-matrix.md`](docs/decision-matrix.md), [ADR-029](adr/ADR-029-cloud-platform-selection.md)  a 10-criterion weighted matrix, every weight traced to a ranked business driver or stated NFR/constraint from `problem-statement.md`/`requirements.md`. | 11. Migration roadmap and ADRs | Done — [`docs/migration-roadmap.md`](docs/migration-roadmap.md), [ADR-030](adr/ADR-030-migration-sequencing-and-rollout-order.md), [ADR-031](adr/ADR-031-us-cutover-mechanism-and-rollback.md)  a 5-phase plan built on one key insight: Solstice's current production traffic is 100% US/Canada, so this is one region's real migration (US) plus two greenfield launches (EU, APAC), not three symmetric rollouts. Greenfield regions launch first, fully decoupled from the higher-risk US cutover, directly de-risking the board-committed EU launch date. The US cutover is a weighted-traffic-shift strangler-fig, component by component (Storefront & Catalog → Cart → Checkout & Payment → Order Orchestration per a coupling-based order), against the *same, unmigrated* database throughout  since today's single RDS instance already holds only US/Canada data, this is a compute-layer migration, not a data migration, which is the single biggest risk reducer in the plan. Rollback is a routing-weight revert, not a data reversal. |
